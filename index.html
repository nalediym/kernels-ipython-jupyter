kernels, ipython, jupyter

A hands-on playground for three words that get conflated constantly. The one idea underneath all of them: you touch a shell, a kernel does the real work.

The three layers

Kernel
The process that runs your code and holds its state.
IPython
The enhanced REPL that the default kernel wraps.
Jupyter
The front-end that talks to a kernel over ZeroMQ.

The lineage

Unix:     shell (bash)        ↔  kernel (Linux)        ← the OG pairing
IPython:  shell (the REPL UI) ↔  kernel (ipykernel)    ← borrowed the metaphor
Jupyter:  front-end (browser) ↔  kernel (any language) ← inherited it, 2014

What's inside

It's built to be felt, not just read: an interactive progression from Unix to IPython to Jupyter, a from-scratch track that rebuilds the stack the way history did, a sniffer that prints the raw ZeroMQ frames between a kernel and its client, and a notebook that's dead until you give it a kernel. All of it runs.
